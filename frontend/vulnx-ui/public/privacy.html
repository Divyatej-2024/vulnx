VulnX Vulnerability Intelligence

Privacy Policy

Last reviewed: 26 October 2026

This policy describes the current VulnX web application. It must be reviewed against the final production infrastructure and Android release before publication.

Current scope: VulnX is a public vulnerability-intelligence dashboard. The current frontend does not provide user registration, advertising, or intentional analytics tracking. This does not exclude technical logs processed by independent hosting providers.

1. Information handled

  • Public vulnerability records: The app requests CVE identifiers, descriptions, publication dates and severity data from the VulnX API for search, filtering and statistics.
  • Browser cache: The progressive web app can cache its app shell and previously requested public vulnerability responses to support faster loading and limited offline access. This data is stored by the browser on your device and can be removed using browser site-data controls.
  • Technical request information: Hosting, CDN, API or network providers may process IP addresses, request timestamps, browser/device metadata and diagnostic logs to deliver, maintain and protect the service. Exact fields and retention depend on provider configuration and policies and must be confirmed by the operator.
  • External resources: The current stylesheet references Google Fonts. The browser may connect to Google's servers to load fonts and disclose technical connection information to that provider. Self-hosting fonts can reduce this third-party request.

2. Purpose and legal basis

VulnX uses public vulnerability data to operate its dashboard. Technical processing by providers may be necessary to deliver and secure the service. The operator must assess and document the applicable legal basis, notices and consent requirements for the actual deployment and jurisdictions served. The in-app notice acknowledgement is not consent to optional analytics or advertising.

3. Sharing and service providers

VulnX does not intentionally sell personal information. Requests are sent to the configured VulnX API, and infrastructure providers may process connection data as part of hosting and security operations. External resources such as the National Vulnerability Database (NVD) apply their own policies. The final release policy must identify actual providers and any additional SDKs or integrations.

4. Permissions

The current web frontend does not request access to device location, contacts, camera, microphone, SMS or call logs. A future Android package should request only permissions essential to implemented and clearly described features. Audit the final Android manifest and bundled SDKs before completing Play Console declarations.

5. Security

Use VulnX over HTTPS. The service should apply least-privilege database access, strict CORS allow-lists, input validation, rate limiting where appropriate, safe error responses, dependency updates and monitored security headers. No internet-connected service can guarantee absolute security; security concerns can be reported through the repository contact channel below.

6. Retention and deletion

The browser cache can be cleared through browser site-data settings. Server-side log retention is controlled by hosting/API providers and must be confirmed by the operator. The current frontend does not create app accounts or maintain user profiles. If account creation or other personal-data storage is added, implement an in-app deletion path, an external deletion request page and a documented retention process before release.

7. Children and target audience

VulnX is a technical vulnerability-information tool and is not designed specifically for children. The Play Console target-audience declaration must match the intended audience and actual app content. Applicable child-safety and privacy requirements must be reviewed before choosing an age group.

8. Changes

Update this policy whenever data practices, SDKs, providers or app features change. The date above should reflect the latest substantive review.

9. Contact and security reports

For privacy questions or security reports, contact the VulnX maintainer through the VulnX GitHub issue page. Do not include passwords, access tokens or other secrets in a report. Configure a monitored privacy/security contact before publishing on Google Play.

Working draft based on the current repository. Verify it against the deployed infrastructure and final Android package. This is not legal advice.
