VulnX Vulnerability Intelligence

Privacy Policy

Last reviewed: 26 October 2026

This policy describes the current VulnX web application. It must be reviewed against the final production infrastructure and Android release before publication.

Current scope: VulnX is a public vulnerability-intelligence dashboard. The current web frontend and native app do not provide user registration, advertising, or intentional analytics tracking. This does not exclude technical logs processed by independent hosting providers.

1. Information handled

  • Native app settings and cache: The mobile app stores the API server address selected by the user and caches public vulnerability lists, summary statistics, and vulnerability details in on-device app storage for offline viewing. This cache is not a user account. It can be removed by clearing the app's storage or uninstalling the app.
  • API requests: When you search, filter, refresh or open a CVE, the app sends the corresponding request to the configured API server. The server receives the request and may receive the device's network IP address and requested search/CVE parameters as part of ordinary HTTP networking. Use only an API server you trust. Production app builds require HTTPS for API connections.
  • Public vulnerability records: The app requests CVE identifiers, descriptions, publication dates and severity data from the VulnX API for search, filtering and statistics.
  • Browser cache: The progressive web app can cache its app shell and previously requested public vulnerability responses to support faster loading and limited offline access. This data is stored by the browser on your device and can be removed using browser site-data controls.
  • Technical request information: Hosting, CDN, API or network providers may process IP addresses, request timestamps, browser/device metadata and diagnostic logs to deliver, maintain and protect the service. Exact fields and retention depend on provider configuration and policies and must be confirmed by the operator.
  • External resources: The current stylesheet references Google Fonts. The browser may connect to Google's servers to load fonts and disclose technical connection information to that provider. Self-hosting fonts can reduce this third-party request.

2. Purpose and legal basis

VulnX uses public vulnerability data to operate its dashboard. Technical processing by providers may be necessary to deliver and secure the service. The operator must assess and document the applicable legal basis, notices and consent requirements for the actual deployment and jurisdictions served. The in-app notice acknowledgement is not consent to optional analytics or advertising.

3. Sharing and service providers

VulnX does not intentionally sell personal information. Based on the current deployment configuration and repository, the following services are involved or may be involved:

  • Vercel: hosts the public web frontend and the deployed API endpoint. Vercel may process request and security logs under its own policies. See Vercel's Privacy Policy.
  • Supabase: the project uses a Supabase database for vulnerability records. The operator must confirm the active project region, logging configuration, backups and retention settings. See Supabase's Privacy Policy.
  • National Vulnerability Database (NVD): the service imports public vulnerability information from NVD. VulnX does not need to send personal profile information to retrieve public CVE feed data. See NIST's Privacy Policy.
  • Google Fonts: the web frontend currently references fonts hosted by Google. Loading these fonts may cause the browser to connect to Google and disclose technical connection information. See Google's Privacy Policy. Self-hosting fonts would reduce this third-party request.

These are the providers indicated by the current deployment and source. The operator must still check the active Vercel and Supabase settings, deployed functions, monitoring integrations and final Android dependency tree before publication. Exact log fields and retention periods cannot be confirmed from source code alone; do not publish guessed retention periods.

4. Permissions

The native app's current features require internet access to retrieve public vulnerability records. The app does not need location, contacts, camera, microphone, SMS, call logs or phone-state access. The Android configuration explicitly requests internet access and blocks several unrelated sensitive permissions where supported by Expo config; the final merged Android manifest must still be inspected because dependencies can contribute permissions. The web frontend also loads Google Fonts from Google's servers, which may disclose technical connection information to that provider.

5. Security

Use VulnX over HTTPS. The service should apply least-privilege database access, strict CORS allow-lists, input validation, rate limiting where appropriate, safe error responses, dependency updates and monitored security headers. No internet-connected service can guarantee absolute security; security concerns can be reported through the repository contact channel below.

6. Retention and deletion

The web browser cache can be cleared through browser site-data settings. Native app settings and cached records can be removed by clearing the app's storage or uninstalling the app. Server-side log retention is controlled by hosting/API providers and must be confirmed by the operator. The current web frontend and native app do not create app accounts or maintain user profiles. If account creation or other personal-data storage is added, implement an in-app deletion path, an external deletion request page and a documented retention process before release.

7. Children and target audience

VulnX is a technical vulnerability-information tool and is not designed specifically for children. The Play Console target-audience declaration must match the intended audience and actual app content. Applicable child-safety and privacy requirements must be reviewed before choosing an age group.

8. Changes

Update this policy whenever data practices, SDKs, providers or app features change. The date above should reflect the latest substantive review.

9. Contact and security reports

For privacy questions, the current public contact route is the VulnX GitHub repository. GitHub issues may be public: do not post personal data, private correspondence, passwords, access tokens, or details of an unpatched security issue there. The maintainer should configure a monitored privacy contact address and private security-reporting channel before public Google Play release.

Working draft based on the current repository. Verify it against the deployed infrastructure and final Android package. This is not legal advice.
